# Paperhue v0.3.1 — Cards, calendar backgrounds, new pages, sync everywhere

Status: design agreed with the owner on 2026-10-12 (brainstorming). Builds on
v0.3.0 (calendar pages from iCal, message board, photo crop, 4K cap, 50 MP
refusal, zh/en switch). Cross-platform rules stay in `shared/` (PROTOCOL.md,
LAYOUTS.md, AGENDA.md, BOARD.md, CROP.md, LANGUAGE.md).

## Intent

The device sits on the owner's office desk. People who come by should see a
status ("暫離", "開會中，15:00 回來"), or a meme with a short dialogue, or a
quote the owner typed. Text is short to medium: a few words up to a few dozen
characters, never long prose. Most of this is done from a phone, often after
leaving the desk, so changing what the device shows must take a few taps.
On a computer the owner can also prepare images in other tools and push them
as photos, but the desktop apps get the same features anyway.

The calendar pages should be able to sit on the owner's own photo, and the
device should be useful straight after setup even with no calendar
configured. The iPhone version must be full-featured despite running in a
browser (Bluefy).

## Goals

1. **Cards (牌卡)** on every app (Windows, macOS, phone web app used on
   iPhone via Bluefy, Android app):
   - Home screen "我的牌卡 / My cards": saved cards as 5:3 thumbnails. One tap
     pushes a card to the device. Cards can be preloaded into the device's
     card pages; tapping a card that is already on a device page only switches
     the page (no upload, one panel redraw).
   - Editor (like adding text to an Instagram story): a card = one background
     (a photo with the existing crop editor, or one of the 7 panel colours) +
     text boxes the user adds, drags, resizes (pinch on phones, handles /
     wheel on desktop), colours (7 inks) and outlines (outline on/off, e.g.
     white text with black outline for text on photos). Live 7-colour preview.
   - Cards and their backgrounds are stored only on the device that made them;
     export / import of cards as a file works between all apps.
2. **Calendar backgrounds**: every calendar page can have its own background
   photo (crop only — no other photo editing). The page layout stays fixed;
   text is drawn directly on the photo as white text with a black outline
   (the owner chose this over cards/plates and over a split layout). Colour
   marks (event dots, bars) get an outline too. The photo is dithered as
   usual; text and marks are drawn crisp in pure panel colours. Without a
   background the pages look exactly as in v0.3.0.
3. **Calendar page kinds**: existing 本日＋月曆 (today + mini month, id
   `month`), 本日行程＋一週行程 (today + week, id `agenda`), 待辦 (id `todo`),
   plus new **日** (day-only page: big date, weekday, today's events) and new
   **月曆** (full-page month grid: Sundays in red, event dots, short titles
   where cells are big enough; holidays are ordinary events from the user's
   calendars, not detected or coloured specially). Apple-style like the existing pages (shared/LAYOUTS.md).
4. **Calendar sources**:
   - Windows: iCal addresses (as v0.3.0).
   - macOS: iCal addresses, same as Windows.
   - iPhone: the phone's own Calendar and Reminders (all accounts the user
     already has there), read by the Paperhue Shortcut — no iCal address on
     the phone. iCal feeds can be subscribed in the iPhone Calendar app and
     then arrive the same way.
   - Android: the phone's own calendars (default, needs the calendar
     permission) plus optional iCal addresses (for calendars not on the phone
     and for to-dos; the Android app fetches them natively, no CORS).
   - No calendar at all on any platform: show the public Taiwan holidays
     calendar by default. The web app reads it from a same-origin copy that
     CI refreshes daily on the GitHub Pages site (public data only).
   - Holidays are not handled specially: they appear only if they are in the
     user's calendars (or in the default calendar above).
5. **Scheduled updates** at the user's daily times (default 06:00, 12:00,
   18:00):
   - Windows: Task Scheduler (exists).
   - macOS: a launchd LaunchAgent running a headless sync while logged in.
   - Android: background work without opening the app (Bluetooth on; the app
     asks to be excluded from battery optimisation so runs are not delayed).
   - iPhone: a ready-made "Paperhue 同步" Shortcut (iCloud link). The user
     creates a Time-of-Day personal automation in the Shortcuts app and picks
     "run immediately" or "ask first" (iOS does not let us share
     automations). When it runs: the Shortcut reads the phone's calendars
     and reminders, opens the Paperhue page in Bluefy with that data, the
     page reconnects to the remembered device without a tap, draws the pages
     and uploads only the changed ones. The phone must be unlocked; Bluefy is
     in front for about 1–3 minutes. The page's 立即同步 button runs the same
     Shortcut.
   - Every platform uploads only pages that changed.
6. **iPhone storage**: cards, backgrounds, settings and last-sent page hashes
   in the browser's IndexedDB, treated as a cache (iOS may clear website data
   of an app unused for a while); export / import backup; the README warns
   about it.
7. **README**: a clear step-by-step section for the iPhone Shortcut (install,
   automation, both run modes, locked-phone limitation) and for Bluefy.

## Non-goals

- Photo editing beyond choosing the crop (no fading, filters, brightness).
- Special holiday handling or a bundled holiday table.
- Accounts, a cloud service, or any server that sees user data.
- Changes to the device itself.
- Upload speed tuning (separate follow-up).

## Anti-goals (failure even if it works)

- Changing the desk status takes more than a few taps on the phone.
- Any feed address, photo or card leaves the user's own devices (the
  public Taiwan holiday copy is the only data we host).
- iPhone users need to paste iCal addresses or set up a server.

## Constraints

- Panel 800×480, 7 colours; all drawings use pure panel colours; photos
  dithered (Stucki with the grain setting).
- Photos (card backgrounds, calendar backgrounds, photo pages) are decoded at
  min(their own size, the 4K cap) and cropped/resized from that full image;
  never from a smaller preview or canvas copy (owner decision 2026-10-12, so
  zoomed crops stay sharp). Preview images are for display only.
- Existing rules: app name Paperhue; hardware = 裝置 / device; 4K cap and 50 MP refusal; crop
  rules (shared/CROP.md, pixels of the capped photo); zh/en switch on every
  UI; calendar data never stored on disk on desktop apps; feed addresses are
  secrets.
- Python is the reference implementation: every new drawing (cards, backgrounds
  on calendar pages, day and month pages) gets goldens in `shared/` that the
  other implementations must match for text placement.

## Delivery order (agreed)

1. Shared foundations + Windows: card format and renderer, calendar
   backgrounds, day and month pages (Python reference + goldens); Windows card
   editor and background settings.
2. Phone web app (iPhone + Android): card home and editor, photos, calendar
   pages, local storage + backup, the default Taiwan calendar copy.
3. iPhone Shortcut sync (Shortcut, page intake, reconnect without a tap) and
   the README.
4. Android: phone calendars and background scheduled updates.
5. macOS: cards, backgrounds, new pages, launchd — in parallel as soon as
   step 1's specs and goldens exist.

## Calls made by the designer (not discussed with the owner)

- Cards are a new page kind 牌卡 (id `card`); the v0.3.0 留言板 (sticky notes)
  and 大字留言 pages stay as they are for quick text-only posting.
- Limits: up to 8 text boxes per card, up to 80 characters per box, wrapping
  inside the box.
- macOS uses iCal addresses like Windows (no system calendar access).
- Card file format: JSON + the background image (PNG/JPEG), packed as one
  `.paperhue-card` zip for export; background photos stored at most at the
  4K cap.

## Calls made after the builder check (owner said: decide, don't stop)

1. Range: Bluetooth only. A phone changes the device only when it is near it;
   no relay or server (anti-goal). The README says so. Preloaded cards and the
   device's own button cover "switch quickly".
2. Tapping a card that is not on the device replaces the card page on screen
   if it is a card page, otherwise the lowest-numbered card page. With no card
   page the app offers, in one confirmation tap, to turn the photo page (or
   page 4) into a card page. Default page kinds stay (1 本日＋月曆, 2 本日行程＋一週行程,
   3 待辦, 4 照片).
3. Several apps, one device: page assignments, backgrounds and cards are per
   app. Scheduled sync redraws only calendar-kind pages and never touches
   card, photo or board pages. The README recommends one scheduling app per
   device and the same page plan in every app used.
4. Scheduled sync with the device out of range: Android retries every 15
   minutes for up to 2 hours after the scheduled time, then skips and logs;
   the iPhone page gives up after about 60 s without finding the device and
   says so; the README suggests times when the phone is at the desk. The day
   page shows the last synced day until the next sync.
5. Red days on the month page: Sundays only. Holidays are events like any
   other. The default calendar (no user calendars) is Google's public Taiwan
   holidays iCal; native apps fetch it directly, the web app reads the daily
   CI copy on the GitHub Pages site.
6. Baseline: v0.3.0 is still landing — Windows gets the zh/en switch, crop
   editor and shared/LANGUAGE.md in v0.3.0; macOS is porting the calendar
   pages and board for v0.3.0 now. macOS v0.3.1 work starts after that port.
7. Android ships as an APK on GitHub Releases (sideload), not on Google Play;
   a release signing key is created for it and kept as a GitHub Actions
   secret plus an offline backup on the owner's PC.
